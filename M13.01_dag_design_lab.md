## Step 1: Understand DAG Design Notation (5 minutes)

+------------------------+-----------------------------------------------------+---------------------------------------------------+
| Diagram Type           | Notation Example                                    | What it means                                     |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| **Text Diagram**       | `[task_a] --> [task_b] --> [task_c]`                | Linear flow: task_a must complete,                |
|                        |                                                     | then task_b runs, then task_c runs                |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| **Text Diagram**       | `[task_a] --> [task_b]`                             | task_a must finish before task_b can start        |
|                        |                                                     | (basic dependency)                                |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| **Text Diagram**       | `[task_a] --\`                                      | Fan-in pattern: Both task_a AND task_b            |
|                        | `           --> [task_d]`                           | must complete before task_d can start             |
|                        | `[task_b] --/`                                      | (AND condition)                                   |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| **Airflow Pseudocode** | `task_a >> task_b >> task_c`                         | Same as linear flow: task_a → task_b → task_c     |
|                        |                                                     | (>> means "runs before")                          |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| **Airflow Pseudocode** | `[task_a, task_b, task_c] >> task_d`                 | Fan-in: All three tasks (a,b,c) run in parallel,  |
|                        |                                                     | but ALL must complete before task_d starts        |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| **Airflow Pseudocode** | `task_a >> [task_b, task_c]`                         | Fan-out: After task_a completes, both task_b      |
|                        |                                                     | AND task_c can run in parallel                    |
+------------------------+-----------------------------------------------------+---------------------------------------------------+

+------------------------+-----------------------------------------------------+---------------------------------------------------+
| **Key Rule**           | Notation                                            | Behavior                                          |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| Rule 1                 | `>>`                                                | Means "runs before" (sets downstream dependency)  |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| Rule 2                 | `[task_a, task_b]`                                   | Tasks in brackets run in parallel                 |
|                        |                                                     | (no dependency between them)                      |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| Rule 3                 | Implicit in fan-in patterns                         | A task only runs when ALL its upstream tasks      |
|                        |                                                     | succeed (AND condition)                           |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| Rule 4                 | Default failure behavior                            | If a task fails, ALL downstream tasks are         |
|                        |                                                     | skipped (unless overridden with triggers)         |
+------------------------+-----------------------------------------------------+---------------------------------------------------+

+------------------------+-----------------------------------------------------+---------------------------------------------------+
| **Visual Examples**    |                                                     |                                                   |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| Linear Chain           | `[extract] --> [transform] --> [load]`              | Sequential steps: Can't transform until extract   |
|                        | `extract >> transform >> load`                       | done; can't load until transform done             |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| Parallel Processing    | `[scrape_a] --\`                                     | Web scraping example: Both sources must be        |
|                        | `            --> [combine_data]`                    | scraped before combining results                  |
|                        | `[scrape_b] --/`                                     |                                                    |
|                        | `[scrape_a, scrape_b] >> combine_data`               |                                                    |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| Fan-out                | `[prepare_data] --> [model_a]`                       | After data prep, train multiple models in         |
|                        | `               --> [model_b]`                       | parallel                                          |
|                        | `prepare_data >> [model_a, model_b]`                 |                                                    |
+------------------------+-----------------------------------------------------+---------------------------------------------------+
| Complex DAG            | `[task_a] --> [task_b] --\`                          | Mixed pattern: task_a → task_b, both task_b       |
|                        | `                  --> [task_d]`                     | and task_c must complete before task_d            |
|                        | `[task_c] -----------/`                              |                                                    |
+------------------------+-----------------------------------------------------+---------------------------------------------------+

from airflow import DAG
from airflow.operators.python import PythonOperator, BranchPythonOperator
from airflow.operators.email import EmailOperator
from datetime import datetime, timedelta

def decide_branch(**context):
    """
    Branch function: returns the task_id of the next task to execute.
    Only ONE branch runs — the other is completely skipped.
    """
    validation_result = context["ti"].xcom_pull(task_ids="validate_data")
    
    if validation_result == "passed":
        return "transform_data"       # Valid path - continue processing
    else:
        return "quarantine_data"      # Invalid path - quarantine and alert

with DAG(
    dag_id="data_quality_pipeline",
    start_date=datetime(2024, 1, 1),
    schedule_interval="@daily",
    catchup=False,
    default_args={
        'retries': 1,
        'retry_delay': timedelta(minutes=5),
    }
) as dag:

    extract_data      = PythonOperator(task_id="extract_data", 
                                       python_callable=extract_fn)
    
    validate_data     = PythonOperator(task_id="validate_data", 
                                       python_callable=validate_fn)
    
    branch_on_quality = BranchPythonOperator(task_id="branch_on_quality", 
                                            python_callable=decide_branch)
    
    transform_data    = PythonOperator(task_id="transform_data", 
                                       python_callable=transform_fn)
    
    load_to_warehouse = PythonOperator(task_id="load_to_warehouse", 
                                       python_callable=load_fn)
    
    quarantine_data   = PythonOperator(task_id="quarantine_data", 
                                       python_callable=quarantine_fn)
    
    send_alert        = EmailOperator(task_id="send_alert", 
                                      to="data-team@company.com",
                                      subject="Data Quality Pipeline Failed",
                                      html_content="Data validation failed and has been quarantined")

    # Linear lead-in
    extract_data >> validate_data >> branch_on_quality

    # Valid path
    branch_on_quality >> transform_data >> load_to_warehouse

    # Invalid path
    branch_on_quality >> quarantine_data >> send_alert

|--------------------|----------------------|-----------------------------------------|---------------------------|
| Fan-In             | API extraction fails | Exponential backoff for rate limits     | Pagination, date filters  |
| Fan-In             | merge_data fails     | Check data quality, increase memory     | Deterministic join        |
| Fan-In             | One extraction slow  | Add task timeout, alert on SLA breach   | Parallelism minimizes     |
|--------------------|----------------------|-----------------------------------------|---------------------------|
| Branching          | quarantine_data fails| CRITICAL: Add 3 retries + PagerDuty    | Atomic move (copy+delete) |
| Branching          | validate_data errors | Try/except, separate monitoring         | Pure validation function  |
| Branching          | send_alert fails     | Store in DLQ, manual resend possible    | Email is informational    |
