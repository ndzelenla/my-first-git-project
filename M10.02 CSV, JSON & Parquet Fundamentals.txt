## CSV vs JSON Comparison Table
=====================================================================================================================
| Aspect                | CSV                                                | JSON                                   |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Schema Enforcement    | No schema - position-based, headers optional      | Self-describing - field names in data,|
|                       | No data type information - all text               | preserves types, supports nesting     |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Read Performance      | Very fast - simple parsing, streaming capable     | Moderate - complex parsing,           |
|                       | 100-200 MB/sec                                    | higher overhead, 20-50 MB/sec         |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Human Readability     | Good for tabular data, requires headers for       | Excellent - hierarchical structure    |
|                       | context, difficult with many columns              | clear, self-documenting field names   |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Typical Use Cases     | - Database exports                                 | - REST APIs                           |
|                       | - Spreadsheet data                                 | - Configuration files                 |
|                       | - Machine learning datasets                        | - NoSQL databases                     |
|                       | - Financial data                                   | - Web applications                    |
|                       | - Legacy system integration                        | - IoT/sensor data                     |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Pros                  | ✓ Universally supported                            | ✓ Hierarchical data support           |
|                       | ✓ Compact file size                                | ✓ Self-describing                     |
|                       | ✓ Fast parsing                                     | ✓ Data types preserved                |
|                       | ✓ Streamable                                       | ✓ Flexible schema                     |
|                       | ✓ Opens in Excel                                   | ✓ Web native                          |
|                       | ✓ Simple to generate                               | ✓ Nested structures                   |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Cons                  | ✗ No hierarchy support                             | ✗ Verbose (larger files)              |
|                       | ✗ No data types                                    | ✗ Slower parsing                      |
|                       | ✗ Position dependent                               | ✗ Higher memory usage                 |
|                       | ✗ Escaping issues with commas/quotes               | ✗ No comments allowed                 |
|                       | ✗ Poor for complex data                            | ✗ Spreadsheet tools struggle          |
|                       | ✗ Missing values need placeholders                 | ✗ Deep nesting gets complex           |
|-----------------------|----------------------------------------------------|----------------------------------------|
| File Size (same data) | Baseline (1x)                                      | 2x - 10x larger                       |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Streaming Support     | Excellent - line-by-line processing                | Limited - needs complete objects      |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Data Type Support     | Text only                                          | String, Number, Boolean, Null, Object,|
|                       |                                                    | Array                                 |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Query Capability      | Limited - line by line scan                        | Better with JSONPath, jq              |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Editing Ease          | Easy in spreadsheets                               | Easy in text editors, IDEs            |
|-----------------------|----------------------------------------------------|----------------------------------------|
| Error Tolerance       | High - can skip malformed rows                     | Low - must be valid or fails entirely |

#### Explain Parquet characteristics:
=====================================================================================================================
| Feature                | Description                                                               | Benefit for Analytics                 |
|------------------------|---------------------------------------------------------------------------|---------------------------------------|
| Columnar Storage       | Data stored column-by-column, with values from each column grouped        | Reads only columns needed by query,   |
|                        | together in contiguous blocks across row groups and pages                 | reducing I/O by 90-99%               |
|------------------------|---------------------------------------------------------------------------|---------------------------------------|
| Compression            | Multiple codecs (Snappy, Gzip, Zstd, LZ4) with column-specific encoding   | 5-15x storage reduction, lower        |
|                        | like RLE, dictionary, delta, and bit-packing                              | cloud costs, more data in memory      |
|------------------------|---------------------------------------------------------------------------|---------------------------------------|
| Metadata               | Stores schema, row group info, column chunk offsets, encodings, and       | Enables query planning, parallel      |
|                        | page-level information in a footer                                        | processing, and efficient access      |
|------------------------|---------------------------------------------------------------------------|---------------------------------------|
| Statistics             | Min, max, null count, distinct count, and optional sum per column         | Predicate pushdown skips irrelevant   |
|                        | chunk and page                                                            | data without reading it               |
|------------------------|---------------------------------------------------------------------------|---------------------------------------|
| Schema Evolution       | Supports adding/removing columns, nested structures (structs, lists,      | Can evolve data models without        |
|                        | maps), and complex data types                                             | rewriting entire datasets             |
|------------------------|---------------------------------------------------------------------------|---------------------------------------|

### Step 4: Conversion Discussion (10 mins)
## Explain the data lake pattern:


---

## Stage-by-Stage Explanation

### Raw Layer (Bronze) - CSV/JSON

| Element | Description |
|---------|-------------|
| **Purpose** | Immutable landing zone for raw data exactly as received from sources |
| **Format** | CSV, JSON, or original source format (no transformation) |
| **Characteristics** | - Append-only, never modified<br>- Full historical record<br>- No schema enforcement<br>- Can contain duplicates, errors<br>- Original data types lost (CSV) |
| **Storage pattern** | `/raw/{source}/{date}/file.{csv,json}` |
| **Access patterns** | - Rarely queried directly<br>- Used for reprocessing<br>- Debugging data issues<br>- Audit/compliance |
| **Example** | `/raw/transactions/2024-01-01/export.csv` |

---

### Transformation Stage (ETL/ELT)

| Element | Description |
|---------|-------------|
| **Purpose** | Clean, validate, optimize, and convert data for analytics |
| **Tools** | Apache Spark, Databricks, AWS Glue, dbt, Dataflow |
| **Operations** | - Read raw CSV/JSON<br>- Parse and validate schema<br>- Handle missing values<br>- Deduplicate records<br>- Join with reference data<br>- Convert data types<br>- Write as Parquet<br>- Partition/compact files |
| **Frequency** | Batch (daily/hourly), micro-batch, or streaming |
| **Key considerations** | - Idempotency (re-runnable)<br>- Incremental processing<br>- Data quality checks<br>- Lineage tracking |

---

### Curated Layer (Silver) - Parquet

| Element | Description |
|---------|-------------|
| **Purpose** | Cleaned, validated, and optimized dataset ready for analysis |
| **Format** | Parquet (columnar, compressed) |
| **Characteristics** | - Schema enforced with proper data types<br>- Deduplicated and validated<br>- Optimized for query performance<br>- Partitioned by common filters<br>- 5-15x smaller than raw<br>- Contains full detail (not aggregated) |
| **Storage pattern** | `/silver/{table}/year=2024/month=01/part-*.parquet` |
| **Access patterns** | - Ad-hoc analytics<br>- Data exploration<br>- Building aggregates<br>- Machine learning feature extraction |
| **Example** | `/silver/transactions/year=2024/month=01/part-00001.parquet` |

---

### Aggregated Layer (Gold) - Parquet

| Element | Description |
|---------|-------------|
| **Purpose** | Business-level aggregates, metrics, and denormalized datasets |
| **Format** | Parquet (optimized for specific use cases) |
| **Characteristics** | - Pre-aggregated for common queries<br>- Denormalized for joins<br>- Business logic applied<br>- Smaller than silver layer<br>- Ready for BI tools |
| **Storage pattern** | `/gold/{business_domain}/{aggregation}.parquet` |
| **Access patterns** | - BI dashboards<br>- Reporting<br>- KPIs and metrics<br>- Customer-facing analytics |
| **Example** | `/gold/daily_sales_by_region/year=2024/month=01/daily_sales.parquet` |

---

### Analytics Consumption

| Element | Description |
|---------|-------------|
| **Purpose** | Query and analyze curated data for business insights |
| **Tools** | - BI: PowerBI, Tableau, Looker<br>- SQL: Presto, Athena, Spark SQL<br>- ML: TensorFlow, PyTorch, Scikit-learn<br>- Python: Pandas, Dask |
| **Query patterns** | - Dashboards (Gold layer)<br>- Ad-hoc analytics (Silver layer)<br>- ML training (Silver features)<br>- Historical analysis (Silver full history) |
| **Performance** | - 10-100x faster than querying raw data<br>- Lower costs due to compression<br>- Better user experience |
